# 実装指示書｜「01 診断メディア」ページ 学生成果物セクションの実装

## 1. 前提

- 対象サイト: `2026-07-02メディア表現発展演習ⅠWebサイト`（Astro + Tailwind v4）
- 対象ページ: `01 診断メディア｜メディア表現発展演習Ⅰ`（高尾担当回・個別授業ページ）
- 対象箇所: ページ内 `<section id="outcomes">`（見出し「学生成果物」）
  - 現状は以下の「準備中」プレースホルダのみ：
    ```html
    <div class="mt-6 border border-dashed p-8 border-takawo">
      <p class="font-mono text-xs uppercase tracking-wider text-ink-soft">準備中</p>
      <p class="mt-3 text-sm leading-relaxed text-ink-soft">
        履修者の提出後、2026年7月中旬より順次公開しました。
      </p>
    </div>
    ```
  - このブロックを本実装のコンポーネントに置き換える。

- データ出典: Notion「学生 課題提出一覧」DB（診断メディア設計反省ページ配下）および「提出課題の分析」ページ。
  - **本実装ではNotionへのライブ連携は行わない。** 静的サイトのビルド時にJSONを読み込む方式とする（Notion APIキーをフロントに露出させないため）。
  - 添付データは事前に匿名化済み（氏名・学籍番号を除去、連番IDに置換）。追加・更新が必要な場合は `src/data/notable-submissions.json` を直接編集する。

## 2. 個人情報マスキング方針（厳守）

| 項目 | 扱い |
|---|---|
| 学生名 | **表示しない**。データにも含めない |
| 学籍番号 | **公開HTML上には表示しない**。`internal.student_id` / `internal.student_id_last3` として、後日の内部トラッキング用にJSON内には保持する（下記3-1参照） |
| 提出物ID | `student-01`〜`student-16` の連番コードのみ使用（学籍番号とは無関係の表示専用ID） |
| 内容要約 | Notionの「内容」列をベースに、個人が特定されうる記述（インタビュー相手の詳細属性、個人の実体験エピソード等）を削除・一般化 |
| Wordファイル添付 | **サイトに掲載しない**（Notion内限定。原本ファイルは提出物のため公開範囲外） |

### 3-1. `internal` フィールドの扱い（学籍番号の保持）

`notable-submissions.json` の各エントリに `internal.student_id`（学籍番号full）と `internal.student_id_last3`（下3桁）を保持している。用途は後日の内部トラッキング（採点・進路面談・発展協働候補の追跡等）のみで、**公開ページには一切出力しない**。

- `StudentShowcase.astro` は `internal` を型定義はするが分割代入・参照しない。`{...item}` のようなオブジェクトスプレッドをテンプレート内で行わないこと（誤って `data-*` 属性等に漏出するのを防ぐため）。
- ビルド構成上、`src/data/notable-submissions.json` はサーバーサイド（ビルド時）でのみ読み込まれ、クライアントJSへは各エントリのうち実際にJSXへ描画したプロパティしか出力されない。ただし以下は運用上の注意点：
  - このリポジトリが**公開GitHubリポジトリ**の場合、`git log` / リポジトリ本体に学籍番号がそのまま残る。公開リポジトリで運用する場合は、`notable-submissions.json` を `.gitignore` に加えて別途プライベートな場所（ローカル／プライベートリポジトリ／Notion側）で管理し、ビルド時にのみ環境変数等で読み込む方式に変更することを推奨。
  - 内部トラッキングそのものをNotion側（元の「学生 課題提出一覧」DB）で完結させ、このJSONの `internal` は削除する運用も選択肢としてあり得る。今回は高尾の指示に従い保持する形とした。

新しく特筆データを追加する際も、上記表の基準で必ずマスキングしてから `notable-submissions.json` に追加すること。

## 3. 追加ファイル

```
src/
├── components/
│   └── StudentShowcase.astro   ← 新規追加
├── data/
│   └── notable-submissions.json ← 新規追加
└── pages/
    └── (01 診断メディアページの .astro ファイル) ← 編集
```

添付ファイル:
- `StudentShowcase.astro` → `src/components/` に配置
- `notable-submissions.json` → `src/data/` に配置

## 4. ページ側の実装差分

対象の `.astro` ページファイルで以下を実施：

```diff
+ import StudentShowcase from "../components/StudentShowcase.astro";
+ import submissions from "../data/notable-submissions.json";
```

`<section id="outcomes">` 内の「準備中」ブロックを次のように置換：

```diff
  <div>
    <h2 class="font-display text-xl text-ink">学生成果物</h2>
    <p class="mt-2 font-mono text-xs text-ink-soft">履修者の提出後、2026年7月中旬より順次公開しました。</p>
  </div>
- <div class="mt-6 border border-dashed p-8 border-takawo">
-   <p class="font-mono text-xs uppercase tracking-wider text-ink-soft">準備中</p>
-   <p class="mt-3 text-sm leading-relaxed text-ink-soft">
-     履修者の提出後、2026年7月中旬より順次公開しました。
-   </p>
- </div>
+ <StudentShowcase submissions={submissions} />
```

## 5. デザイントークン（既存サイトから流用・新規追加不要）

```css
--color-paper: #f5f2e9;
--color-paper-dim: #ece7d9;
--color-ink: #1c1a15;
--color-ink-soft: #57534a;
--color-line: #d3ccb8;
--color-takawo: #b5722c;   /* 高尾回のアクセントカラー。本セクションもこれに統一 */
```

`StudentShowcase.astro` はTailwindユーティリティクラスのみで構成し、既存の「課題・評価」ブロック（`border-l-2 pl-3 border-takawo` のアクセントバー、`font-mono text-xs uppercase tracking-[0.2em] text-ink-soft` の小見出し）とトーンを揃えている。scoped CSS（`data-astro-cid-*`）は使用していないため、そのまま流用可能。

## 6. 確認事項（実装前に高尾へ確認推奨）

1. 「振り返り」区分の3件は診断企画名を持たないため、カード見出しを「振り返りの記述密度・批判的深度」という区分ラベルで代用している。個別の見出し文言が必要であれば要調整。
2. `note` フィールド（例：「質問項目のレベルが高い」）は1件のみ存在。表示スタイル（現状は本文末尾に小さく強調表示）でよいか確認。
3. Notion側の「特筆学生 課題提出一覧」は今後も更新される可能性がある。更新の都度、本ファイル冒頭の匿名化方針に従い `notable-submissions.json` を手動更新する運用でよいか、もしくはビルドスクリプトでの半自動抽出（Notion API＋匿名化フィルタ）を今後整備するか、方針を決めておくと良い。
